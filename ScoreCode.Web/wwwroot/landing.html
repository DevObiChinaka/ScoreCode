# Q2: return index of target, or -1
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

How it works

Set it, sit it, grade it, release it.

Four moves take an exam from a lecturer's draft to a student's released result.

FAQ

Questions, answered.

How do students take an exam?
They install the Windows desktop app, sign in with their matric number, and enter the exam room at the scheduled time. Code runs on their own machine, so there's no external judge to queue behind, and submissions sync as they go.
Which languages can students use?
Python, Java, C++ and JavaScript run natively, and HTML/CSS get a live preview. Each runs under sensible time and memory limits. The lecturer chooses which languages a given exam allows.
How does AI grading stay fair?
The AI only ever proposes a score with a written rationale. It never finalises anything. The lecturer accepts, adjusts, or overrides, and every override is stored with a reason. Students are identified by matric number only, so grading is blind to identity.
What stops students cheating?
Exams run fullscreen in a locked-down room with common shortcuts blocked and a single active session per matric number. Focus loss and blocked keystrokes are logged to an activity trail the lecturer can review alongside each submission.
Who manages accounts and institutions?
Administrators work in the web portal. An institution applies publicly, a platform admin approves it, and the first admin account is provisioned automatically. That admin then manages lecturers, students, roles and password resets, each institution isolated in its own tenant.
